# NexusAI Trading Terminal Runnable MVP/foundation for an AI-native demo/paper trading terminal. ## What is included - Dark professional trading terminal UI - Watchlist + realtime simulated quotes over WebSocket - Candlestick chart using Lightweight Charts - Demo/Paper account, balance/equity/margin/P&L - Market orders with deterministic Risk Engine - Positions, closing, order history and trading journal - AI Copilot with controlled backend tools - AI market analysis + structured trade proposal - AI trade flow: AI → Proposal → Risk Engine → Paper Execution - Emergency Stop - Configurable risk limits - EMA/RSI/ATR indicators - Basic EMA strategy backtest - Audit log/event model in the backend - Provider-neutral architecture starting point ## Run locally ```bash python -m venv .venv # macOS/Linux: source .venv/bin/activate # Windows: # .venv\Scripts\activate pip install -r requirements.txt uvicorn app:app --reload ``` Open http://127.0.0.1:8000 ## Docker ```bash docker build -t nexus-ai-trading . docker run -p 8000:8000 nexus-ai-trading ``` ## Important architecture boundary This repository is intentionally a DEMO/PAPER trading implementation. It is not a licensed broker, exchange, custody, payments, KYC/AML or production execution system. The critical safety rule is implemented in the design: AI -> Trade Proposal -> Risk Engine -> Order/Execution The AI endpoint cannot override risk limits. In production, the execution provider must remain behind a separate authenticated service boundary and all financial state should be derived from an immutable double-entry ledger. ## Recommended production evolution 1. Replace simulated market loop with a `MarketDataProvider` interface and real adapters. 2. Move state into PostgreSQL and Redis. 3. Add event bus (Kafka/Redpanda/NATS). 4. Split Order Management, Risk, Execution and Ledger into services. 5. Add real backtesting data + realistic execution simulator. 6. Add LLM provider behind an `AIProvider` abstraction and tool permissions. 7. Add OAuth/MFA/RBAC, encrypted secrets and API-key vaulting. 8. Add compliance/payment services only after legal/licensing design. 9. Add observability with OpenTelemetry + Prometheus/Grafana. 10. Add desktop/mobile clients after API contracts stabilize. ## Suggested repo structure for the next phase ```text services/ auth/ accounts/ market-data/ oms/ risk/ execution/ portfolio/ strategy/ backtest/ ai/ notifications/ ledger/ apps/ web-terminal/ desktop/ mobile/ infra/ postgres/ redis/ event-bus/ ```
